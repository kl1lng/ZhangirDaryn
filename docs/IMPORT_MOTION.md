# Перенос готовых жестов из исходного приложения в PWA

Исходный Streamlit хранит клипы в `data/motion_library.sqlite3`, а PWA публикует
только одобренные записи из `data/pwa/public.sqlite3`. Общий репозиторий кода не
синхронизирует эти базы. Перенос выполняется явно для выбранного клипа.

Команда предназначена для локальной SQLite. Для одного клипа:

Предварительный просмотр без записи:

```powershell
.venv-pwa\Scripts\python.exe -m backend.import_motion --source data/motion_library.sqlite3 --clip-id 2
```

Для пакетного предварительного просмотра импортируются только клипы, где
исходные метаданные явно содержат `training_eligible=true` и
`rights_confirmed=true`:

```powershell
.venv-pwa\Scripts\python.exe -m backend.import_motion --source data/data/motion_library.sqlite3 --all-eligible
```

После проверки названия, размеров массива и прав на публикацию:

```powershell
.venv-pwa\Scripts\python.exe -m backend.import_motion --source data/motion_library.sqlite3 --clip-id 2 --apply --confirm-rights
```

Для подтверждённого набора та же команда с `--all-eligible --apply
--confirm-rights`. Перед `--apply` проверьте отчёт без записи и войдите в PWA
настроенным аккаунтом модератора. Клип с неподтверждёнными правами или низким
покрытием рук не попадёт в каталог. Импорт сохраняет координаты; видео остаётся
в исходной папке и не переносится в PWA.

Команда переносит координаты, FPS и данные корпуса; проверяет массив и контрольную
сумму, создаёт запись одобренного материала и локальную проверенную копию артефакта.
Повторный запуск не создаёт дубль и не публикует заново отозванный материал.
Видео и исходная база не изменяются. Пути к файлам и идентификатор исполнителя
из исходных метаданных в публичный артефакт не попадают. Разрешения на обучение
и исследования не назначаются импортом.

После первого переноса обновите страницу PWA. В карточке материала исходник
отмечен как «Не переносился», координаты доступны в словаре и переводчике.

29 октября 2026 года по запросу владельца перенесён клип «сәлем» №2:
56 кадров × 162 признака, 24 FPS, с данными корпуса. Проверено воспроизведение
на настоящем 3D-аватаре. Для размещения эти артефакты должны попасть в закрытую
базу сервера; GitHub хранит код и инструкции, а не рабочую SQLite и видео.

В этот же день выполнен пакетный dry-run и импорт предоставленного локального
набора. Из 249 клипов импортированы 114 с `training_eligible=true` и
`rights_confirmed=true`; 134 не прошли порог отслеживания рук, три не имели
подтверждения прав (два клипа входят в обе группы). Импортированные массивы
упакованы и проверены из резервных копий. В PWA разрешены отображение, но
`training=0` и `research=0`. Видеофайлы остались в исходных папках и не были
загружены на Drive, GitHub или Vercel. Один символ и четыре слова не имеют
клипа, одновременно прошедшего оба фильтра; их надо обработать повторно или
проверить отдельно. Повторный импорт безопасен и идемпотентен.

Для опубликованного словаря без Python-сервера подготовлен снимок из 115 готовых
одобренных записей PWA (54 исходные метки, включая дубли вариантов):
`data/pwa/public-library/20261029-v1`. В нём 41 различная буква и 13 меток слов/фраз.
Только координаты с разрешения владельца опубликованы в Supabase Storage,
`gesture-library/20261029-v1`; видео, профили и рабочая база не переносились.
Подключение и обновление описаны в `docs/DEPLOYMENT.md`.
Буква «Х» не вошла в снимок: исходные клипы 186–189 имеют покрытие распознавания
рук 37–45% и `training_eligible=false`. Порог качества при публикации не снижался.
