# DosYm PWA: сценарии, экраны и архитектура

Дата: 28 октября 2026 года. Статус: исходная спецификация, локальная реализация описана ниже и в `docs/PWA_PROGRESS.md`; живые внешние сервисы пока не подключены.

## 1. Что создаём

Адаптивное приложение казахского жестового языка для ПК и телефона, устанавливаемое как PWA. Пользователь ищет жесты, воспроизводит их на аватаре и после входа через Google может пополнять библиотеку своими видео. Интерфейс размещается на Vercel, исходные видео — на Google Диске через API, извлечённые координаты — независимо от видео в постоянной базе данных.

Подтверждено пользователем:

- Для загрузки обязателен аккаунт с входом через Google.
- Загрузки обычного пользователя проходят модерацию.
- Загрузки модератора автоматически поступают на обработку без отдельного одобрения.
- Координаты должны сохраняться и использоваться после удаления видео.
- Разрешения на публичную обработку/показ, обучение модели и исследовательское использование записей запрашиваются раздельно; обучение и исследования — добровольные.
- Нужны ПК, мобильные устройства, Vercel и индивидуальный, удобный дизайн.
- Первый модератор — указанный пользователем Google-аккаунт. Его адрес не включать в репозиторий; хранить в закрытой серверной настройке.

Предложения, которые пользователь пока отдельно не утверждал:

- Просмотр словаря и демонстрации без входа; загрузки, личная история и синхронизация — после входа.
- Русский и казахский интерфейс; язык интерфейса не подменяет язык жестового корпуса.
- Supabase для Google-входа и PostgreSQL; отдельный Python-сервис для видео и ML.
- Автоматически ставить одобренные данные в очередь подготовки; обучение выполнять пакетами с проверкой качества, а не менять рабочую модель после каждого ролика.
- Удаление исходника — отдельное явное действие после проверки, без автоматического удаления в первой версии.

## 2. На чём строим

Изучены `PROJECT_MAP.md`, `README.md`, `app.py`, `src/project_motion.py`, `src/motion_db.py`, `src/training_data.py`, `src/motion_api.py` и веб-интерфейс. Файл `Projects.md` при предыдущем поиске не найден.

Уже реализованы извлечение координат, хранение сжатого NumPy-массива в SQLite, метаданные позы, сбор обучающих последовательностей, обучение BiLSTM, браузерный аватар и подготовленные дорожки костей. Streamlit оставить локальным инструментом автора для подготовки и диагностики. Публичный интерфейс строить рядом, не переписывать ML-конвейер заново.

Сейчас `web/index.html` обращается к `localhost:8502`. В публичном приложении все такие адреса заменить конфигурацией или относительными API-маршрутами. Встроенные в HTML исходные массивы заменить загрузкой версионированных данных по API. Проверки скелета и воспроизведения сохранить.

Координаты не равны исходному видео: после удаления нельзя заново извлечь детали, которых не было в массиве. Техническое качество трекинга не подтверждает правильность КЖЯ. Текущий ретаргетинг не воспроизводит полноценную мимику; первая версия не обещает свободный перевод любых предложений.

## 3. Варианты реализации

| Вариант | Плюсы | Ограничения |
|---|---|---|
| Обернуть Streamlit в устанавливаемую оболочку | Быстрый локальный эксперимент | Слабый контроль мобильных сценариев, офлайна и публичных ролей; требуется отдельный постоянно работающий сервер |
| Весь сервис в Vercel Functions | Один основной хостинг | Ограничения размера запроса и длительности функций плохо соответствуют видео и обучению |
| Next.js на Vercel + постоянная БД + отдельный Python-сервис | Используем существующий ML-код, надёжные фоновые задачи, полноценный мобильный интерфейс | Кроме Vercel нужны БД и среда выполнения Python |

Рекомендация автора плана — третий вариант. Это предложение, не уже сделанный пользователем выбор всех поставщиков.

## 4. Путь пользователя и экраны

### Первое открытие и регистрация

1. Открывается рабочий экран «Перевод»: короткое объяснение возможностей, поле текста и пример доступного жеста. Длинный рекламный экран не нужен.
2. Кнопка «Добавить видео» для гостя открывает компактный экран входа с кнопкой «Продолжить с Google», ссылками на условия и политику обработки материалов.
3. Выбор аккаунта происходит в официальном интерфейсе Google. Пароли приложение не собирает. Отдельного пароля и повторной формы регистрации нет.
4. Сервер проверяет вход; первый вход создаёт профиль с обычной ролью. Для заранее заданного первого модератора роль выдаётся сервером и привязывается к устойчивому идентификатору аккаунта после подтверждения личности.
5. Короткая настройка: язык интерфейса и отображаемое имя. Запрашивать разрешение на использование видео и обучение следует при отправке материала, а не прятать его в общей регистрации.
6. Возврат к действию, ради которого пользователь входил. При отмене входа сохраняется введённый текст, загрузка не начинается.

### Основные окна

| Экран | Содержание | Основное действие |
|---|---|---|
| Перевод | Ввод текста, очередь найденных жестов, аватар, отсутствующие слова | «Показать жесты» |
| Словарь | Поиск, алфавит/категории, варианты жеста, доступность офлайн | Открыть жест |
| Жест | Крупный аватар, название, скорость, повтор, источник, статус проверки | Воспроизвести / сохранить офлайн |
| Добавить видео | Пошаговая форма, локальный предпросмотр, прогресс передачи | Отправить |
| Мои материалы | Свои загрузки, статус, причина отклонения, повторная отправка | Открыть материал |
| Материал | История обработки, результат, возможность повторить или удалить исходник | Действие по текущему состоянию |
| Профиль | Имя, язык, выход, офлайн-хранилище, запрос удаления данных | Управлять аккаунтом |
| Модерация | Очередь, видео, метка, права, решение с причиной | Одобрить / отклонить |
| Обработка и модель | Очередь задач, ошибки, версии набора и модели; только модератор | Повторить задачу / проверить кандидата |

Камеру для распознавания жестов вынести во второй выпуск: сначала обеспечить качественный цикл пополнения библиотеки. Голосовой ввод текста — дополнительная возможность с обязательным текстовым запасным сценарием.

### Загрузка: четыре понятных шага

1. Выбрать или записать один ролик. Показать пример кадра: видны кисти, плечи и лицо, достаточное освещение. Камеру открывать только после действия человека.
2. Указать слово/букву/фразу, язык и вариант жеста; предложить существующую метку, чтобы не создавать дубликаты. Просмотреть запись, при необходимости выбрать начало и конец.
3. Подтвердить права на материал и отдельно согласие на использование для обучения; пояснить, что останется после удаления исходника. Для записей других людей требуются соответствующие разрешения.
4. Отправить: показать реальный прогресс передачи. После подтверждения сервером — «Ожидает проверки» или «В очереди обработки» для модератора. Дальнейшая обработка продолжается после закрытия страницы.

Проектные ограничения для пилота: один файл за отправку, до 100 МБ и 60 секунд, контейнеры MP4/WebM/MOV только при подтверждённом декодировании. Это предлагаемые ограничения продукта, а не лимиты Google Drive. Проверять реальные тип, длительность, разрешение и целостность на сервере; мобильные форматы испытать до фиксации списка. Повторная отправка того же запроса не создаёт второй материал.

## 5. Модерация и автоматическая обработка

Хранить три независимых состояния:

- Модерация: `pending`, `approved`, `rejected`; для загрузки модератора автоматически `approved` с основанием `trusted_uploader`.
- Обработка: `not_started`, `queued`, `running`, `ready`, `failed`, `needs_video`.
- Исходник: `uploading`, `available`, `delete_requested`, `deleted`, `missing`.

Обычный пользователь: загрузка → серверная техническая проверка → ожидание модерации → одобрение → очередь извлечения → проверка координат → сохранение → доступность одобренного клипа.

Модератор: загрузка → та же техническая проверка → автоматическое одобрение по серверной роли → очередь извлечения → проверка координат → сохранение. Пропускается только человеческое одобрение; проверка формата, прав и качества остаётся.

Отклонение требует причины. Исправленная запись — новая версия с новой проверкой. Пользователь видит только свои непубличные материалы; модератор — очередь. Все решения и автоматическое одобрение записываются в журнал. У модератора должны быть просмотр видео и покадровая/замедленная проверка; уверенность модели не выдавать за лингвистическую экспертизу.

До одобрения материал не попадает ни в публичную библиотеку, ни в обучение. Отозванный или повторно отклонённый материал исключается из новых наборов; связанные опубликованные версии модели помечаются для пересборки, без обещания мгновенного удаления влияния из весов.

Сбой обработки не меняет решение модератора на отклонение. Повтор задачи идемпотентен. У задачи есть число попыток, блокировка с истечением срока и безопасное восстановление после остановки процесса.

## 6. Координаты, удаление и обучение

Сохранять исходные извлечённые последовательности, число и порядок точек, маски пропусков, FPS, границы кадров, размеры/пропорции кадра, версию экстрактора, ориентацию/зеркальность, метку и язык. Руки, лицо, поза и мировые координаты позы — по фактической доступности, без подстановки выдуманных точек. Сохранять происхождение и статус прав. Нормализованные входы обучения и дорожки аватара — производные с собственной версией.

Для пилота сжатые массивы хранить в PostgreSQL как бинарные артефакты с размером, формой, типом и контрольной суммой. Не загружать бинарные поля в списках материалов. Для роста предусмотреть интерфейс хранилища и перенос крупных артефактов в объектное хранилище без изменения идентификаторов клипов. Порог переноса определить измерением объёма и стоимости на пилотном корпусе.

Удаление видео разрешается только когда результат записан транзакционно, перечитан из БД, проходит проверку формы/конечных значений/контрольной суммы и доступен в резервной копии. Для обычной загрузки сначала завершается модерация. Явно предупредить о невозможности повторного извлечения из удалённого исходника. Не использовать каскадное удаление координат при удалении ссылки на Drive.

Порядок удаления: серверная проверка владельца/прав → `delete_requested` → удаление файла через Drive API → фиксация `deleted`. Повторы безопасны; уже отсутствующий файл не удаляет данные. Отдельно предусмотреть «Удалить весь материал»: это другой сценарий, затрагивающий координаты и будущие обучающие наборы.

Обязательный приёмочный опыт: сохранить ролик → проверить координаты → удалить только исходник → перезапустить сервис → воспроизвести клип и собрать из БД обучающую последовательность. Проверка в новой сессии исключает случайную зависимость от памяти или браузерного кэша. Удаление видео ещё не проверено как полноценный сценарий текущего проекта.

Автоматизация ML состоит из двух операций:

1. После одобрения автоматически извлечь координаты и включить подходящий пример в кандидаты набора.
2. Автоматически сформировать задачу обучения накопленного набора; при нехватке классов/независимых исполнителей показать «Недостаточно данных», а не запускать заведомо некорректное обучение. Не запускать параллельное обучение при каждом ролике. Группы train/validation разделять по исполнителям и источникам; зафиксировать контрольный набор.

Рабочая модель остаётся прежней, пока кандидат не прошёл проверку качества и проверку модератором. Сохранять версию набора, параметры, метрики по классам и возможность возврата. Извлечение точек не называть «модель обучилась» в пользовательских статусах.

## 7. Размещение и интеграции

| Часть | Предложение | Назначение |
|---|---|---|
| Интерфейс и короткий API | Next.js, TypeScript, Vercel | Страницы, сессии, проверки доступа, создание задач |
| Аккаунты и постоянная база | Supabase Auth + PostgreSQL | Google-вход, роли, материалы, массивы, очередь, аудит |
| Видео | Google Drive API, закрытая папка проекта | Исходники до проверки/обработки |
| Передача видео и ML | Отдельный контейнерный Python-сервис | Приём частей загрузки, Drive, MediaPipe, задачи извлечения и обучения |
| Аватар | Существующие Three.js и `rig-motion.mjs` | Переиспользование и адаптация проигрывателя |

Для Python нужен выбранный отдельно контейнерный хостинг с достаточными CPU/RAM и возможностью выполнять фоновые задачи. В разработке сервис работает локально; до публичного пилота выбрать провайдера по замерам одного и нескольких роликов, политике хранения и бюджету. GPU не считать обязательным до измерения обучения. Публикация на Vercel сама по себе не размещает этот сервис.

Vercel Functions имеют предел тела запроса/ответа 4,5 МБ и ограничения длительности. Поэтому ролик не проходит целиком через функцию. Браузер получает ограниченный билет загрузки и отправляет части Python-сервису; сервис передаёт их в resumable-сессию Drive. Токен владельца Диска и URI resumable-сессии остаются на сервере. До основной разработки проверить такой транспорт из браузера на реальном мобильном формате и при обрыве сети.

Вход через Google для пользователя запрашивает только идентификацию. Подключение Диска выполняет отдельно владелец хранилища. Для личного Google-аккаунта предлагается серверный OAuth с offline-доступом к созданным приложением файлам (`drive.file`), отдельной папкой и защищённым refresh token. Создание папки приложением и все требуемые операции проверить с выбранным scope. Сервисный аккаунт не имеет собственной квоты хранения; простой доступ к папке личного Диска не решает вопрос владения файлами. Shared Drive — альтернатива при наличии подходящего Google Workspace.

До пилота проверить OAuth consent screen, redirect URI, режим публикации приложения, срок жизни тестовых разрешений, восстановление после отзыва доступа, квоту Диска. Google OAuth credentials, настройки Supabase и токены задаются вне Git. Не просить присылать секреты в чат.

Доступ к видео — через авторизованный сервис с поддержкой диапазонов для просмотра и перемотки; не публиковать ролики по общедоступным ссылкам. Рабочая БД, пользовательские материалы и обученные артефакты не входят в GitHub. Наличие плагина Google Drive в Codex не создаёт Google API-интеграцию для пользователей PWA.

## 8. Визуальное направление и адаптивность

Предлагаемое направление — «пространство жеста»: спокойный светлый интерфейс с большой сценой, где хорошо различимы кисти и лицо. Его узнаваемость создаёт сцена движения и последовательность жестов, а не декоративные карточки.

- Палитра: фон `#F6F8FB`, поверхности `#FFFFFF`, текст `#18283B`, основной синий `#2454B8`, вспомогательный бирюзовый `#147D79`, ошибка `#B42332`. Цветовые сочетания проверить на контраст, не считать эти значения уже аттестованными.
- Шрифт: локально размещённый Noto Sans с проверкой всех казахских букв; размер основного текста от 16 px. Лицензию шрифта включить в notices при добавлении.
- Аватар на спокойной контрастной сцене, без текста и декоративных объектов поверх кистей. Последовательность слов под сценой показывает текущий жест и отсутствующие слова.
- Один основной акцент действия на экране; подписи кнопок называют результат. Движение интерфейса только помогает понять изменение состояния.
- Не использовать шаблонную сетку одинаковых карточек, фоновые градиенты, вымышленные отзывы/показатели и постоянные декоративные анимации.

ПК от 1024 px: боковая навигация, рабочая область до 1440 px; ввод и очередь слева, крупный аватар справа. Модерация: очередь и просмотр рядом.

Планшет 768–1023 px: компактная навигация, адаптация двух колонок по доступному месту. Телефон 320–767 px: одна колонка, аватар целиком, действия доступны большим пальцем; нижняя навигация «Перевод / Словарь / Добавить / Мои». Профиль открывается через аватар аккаунта; модерация доступна из служебного меню роли. В landscape не перекрывать сцену навигацией.

Целевые размеры основных сенсорных кнопок — минимум 44×44 CSS px как внутреннее правило продукта; это не утверждение, что WCAG AA требует именно 44 px. Управление с клавиатуры, видимый фокус, подписи значков, статусы текстом, поддержка reduced motion и масштабирования 200%. Звуковой сигнал не может быть единственным уведомлением. Все критические действия доступны без слуха и голосового ввода.

Перед кодом подготовить три ключевых макета в двух размерах: перевод, загрузка, модерация. Проверить путь пользователя на кликабельном прототипе, затем переносить дизайн в код. Figma установлена и подходит для макетов; Canva установлена и может пригодиться для презентационных материалов. Создание внешних файлов сейчас не выполнялось. Поиск также нашёл неустановленные Product Design и MagicPath; для текущего плана установка не нужна.

## 9. PWA, офлайн и производительность

Манифест, обычные и maskable-иконки, standalone-режим, HTTPS, service worker и страница без сети. На поддерживающих браузерах — установка по действию пользователя; для iOS — инструкция добавления на экран. Установка не обязательна для работы в браузере.

Без сети доступны оболочка и явно скачанные публичные/одобренные жесты с моделью аватара, дорожками и локальными зависимостями. Вход, отправка видео, модерация и серверное обучение требуют сети. Черновик метки можно сохранить локально; первую версию не строить на гарантированной фоновой передаче больших роликов или Background Sync.

Не кэшировать токены, приватные видео и служебные ответы в service worker. Личный локальный кэш очищать при выходе. Версии публичных клипов и кэша связать; удалённый/отозванный публичный жест инвалидировать при следующем подключении. Человек видит размер скачиваемого набора и может очистить его. Обрабатывать нехватку места и вытеснение браузером данных.

Three.js и GLB загружать при открытии сцены, не на странице входа. При недоступном WebGL показать понятное состояние; видеозапись использовать как запасной вариант только когда её публикация разрешена и исходник сохранён. Начальный целевой профиль: не ниже 24 FPS на согласованном среднем телефоне при воспроизведении одного жеста; измерить реальную модель до обещания этой скорости. При скрытой вкладке приостанавливать рендеринг. Обновление PWA предлагать между действиями, не прерывать загрузку.

## 10. Границы первой версии

В первую версию входят Google-вход, роли, приватные загрузки Drive, модерация, автоматическое извлечение, постоянные массивы, воспроизведение, личные статусы, контролируемая подготовка модели, адаптивность и базовый офлайн.

Следующий выпуск: мобильное распознавание камерой, расширенные упражнения, проверенные фразовые корпуса, расширенная мимика и автоматическое расписание обучения после накопления достаточного набора. Оплата, социальная лента и рейтинги не нужны для текущей задачи.

## 11. Проверенные ориентиры и источники

Просмотр открытых страниц выполнен 28 октября 2026 года; не проводился полный аудит чужих приложений. Уникальность относительно всего интернета не доказуема.

- [AI-Ym: о сервисе](https://ai-ym.kz/ru/about): отдельные сценарии словаря, обучения и перевода. Для DosYm полезно отделение задач и указание границ возможностей. Материалы не копировать, права на видео не выводить из их доступности.
- [Sign ASL](https://www.signasl.org/): поиск слова/фразы, варианты и переключение скорости. Использовать как ориентир управления воспроизведением, не как источник данных КЖЯ.
- Spread the Sign: прямое чтение сайта вернуло 403; выводы о его текущем интерфейсе не делались.
- [Vercel Functions: ограничения](https://vercel.com/docs/functions/limitations): размер тела запроса/ответа и длительность выполнения обосновывают отдельный видеосервис.
- [Next.js: PWA](https://nextjs.org/docs/app/guides/progressive-web-apps): манифест, service worker и различия поддержки возможностей браузерами. Экспериментальные API не брать за основу первой версии.
- [Google Drive: загрузка файлов](https://developers.google.com/workspace/drive/api/guides/manage-uploads): resumable-передача с продолжением после сбоя.
- [Google Drive: общие диски](https://developers.google.com/workspace/drive/api/guides/about-shareddrives): владение файлами и ограничения сервисных аккаунтов.
- [Google: серверный OAuth](https://developers.google.com/identity/protocols/oauth2/web-server): offline-доступ и обновление токенов.
- [Google OpenID Connect](https://developers.google.com/identity/openid-connect/reference): проверяемая идентичность и устойчивый идентификатор пользователя.
- [Supabase Auth](https://supabase.com/docs/guides/auth): поддержка социального входа Google.
- [W3C: размеры целей указателя](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum): доступность интерактивных элементов.

## 12. Что требуется перед реализацией и выпуском
