# DosYm PWA Implementation Plan

> **Статус:** план выполняется. Локальные результаты и фактические блокеры — `docs/PWA_PROGRESS.md`; production подключения и проверки на внешних сервисах не выполнялись.

**Цель:** адаптивное PWA с Google-входом, загрузками на Drive, модерацией и независимым хранением координат.

**Архитектура:** Next.js на Vercel обслуживает интерфейс и короткие API-запросы. Supabase Auth/PostgreSQL хранит аккаунты, роли, состояния, координаты и задания; отдельный Python-сервис выполняет передачу видео и ML с переиспользованием `src/`.

**Стек, предложенный автором:** Next.js/TypeScript, CSS с собственными токенами, Supabase, Python, MediaPipe, TensorFlow, Three.js, Google Drive API. Точные совместимые стабильные версии зафиксировать на этапе технического прототипа.

**Спецификация:** [Сценарии, экраны и архитектура](../specs/2026-10-28-dosym-pwa-design.md). Пользователь подтвердил локальную реализацию; для внешнего доступа остаётся настройка Google, PostgreSQL и Vercel.

## Общие ограничения

- Для загрузки обязателен аккаунт с входом через Google.
- Загрузки обычного пользователя проходят модерацию.
- Загрузки модератора автоматически поступают на обработку без отдельного одобрения.
- Координаты должны сохраняться и использоваться после удаления видео.
- Нужны ПК, мобильные устройства, Vercel и индивидуальный, удобный дизайн.
- Первый модератор — указанный пользователем Google-аккаунт. Его адрес не включать в репозиторий; хранить в закрытой серверной настройке.
- Рабочие данные, секреты и пользовательские видео не включать в Git. Текущий Streamlit и пользовательские изменения сохранять.
- Только одобренные и технически пригодные материалы могут участвовать в публикации и обучении.

## Пять критических сценариев проверки

1. Повтор отправки или падение процесса не создаёт дубликат материала/клипа; задания восстанавливаются.
2. Пользователь не получает доступ к чужим исходникам и не может назначить себе роль модератора.
3. Исходник удалён, сервис перезапущен: координаты читаются, аватар воспроизводится, набор обучения собирается.
4. На телефоне оборвалась загрузка, закончилась квота Drive или отозван OAuth: статус правдивый, есть восстановление без потери уже сохранённых результатов.
5. Нет сети, WebGL или места в браузере: интерфейс объясняет ограничение и сохраняет доступные действия.

## Карта изменений

Пути ниже — реализованные модули; некоторые первоначально предполагавшиеся отдельные файлы объединены по ответственности.

| Путь | Ответственность |
|---|---|
| `pwa/` | Next.js-приложение, manifest, responsive shell и Vercel Root Directory |

| `pwa/public/sw.js`, `pwa/public/offline.*` | Service worker, безопасный кэш public assets, статический offline shell |
| `backend/` | FastAPI, роли, SQLite/Postgres store, Drive/local storage, workers и candidate trainer |
| `db/migrations/001_public_pwa.sql` | PostgreSQL таблицы, RLS и запрет браузерного DML |
| `tests/test_pwa_*.py`, `pwa/tests/` | Серверные, security, recovery, TensorFlow и Playwright сценарии |

Из существующего адаптировать ограниченно: `src/motion_db.py`, `src/training_data.py`, `src/project_motion.py`, `src/train.py`, `web/avatar.html`, `web/rig-motion.mjs`. Переносить вычислительные части проигрывателя без параллельной несогласованной копии. Новые общие модули проверять существующими JS-тестами.

## Контракты между этапами

- `Submission`: `id`, `owner_id`, `label`, `language`, `moderation_status`, `processing_status`, `source_status`, `revision`, `created_at`.
- `MotionArtifact`: `id`, `submission_id`, `schema_version`, `extractor_version`, `shape`, `dtype`, `fps`, `checksum`, `payload`, `metadata`.
- `Job`: `id`, `submission_id`, `kind`, `state`, `attempt`, `lease_until`, `idempotency_key`, `error_code`.
- `POST /api/uploads/init`: авторизованный запрос с меткой, языком, MIME, размером и ключом идемпотентности → `submission_id`, ограниченный `upload_ticket`, адрес Python-загрузчика.
- Python API: `PUT /uploads/{id}/chunks` с диапазоном байтов, `GET /uploads/{id}/status`, `POST /uploads/{id}/complete`; проверка билета и роли на сервере, билеты и Drive URI не логировать.
- `GET /api/submissions/{id}` → доступное владельцу/модератору состояние; `POST /api/moderation/{id}/decision` принимает решение, причину и ожидаемую `revision`.
- `POST /api/submissions/{id}/delete-source` удаляет только видео; полное удаление материала — отдельная операция и интерфейс.
- `GET /api/gestures`, `GET /api/gestures/{id}/motion` возвращают только разрешённые версии; метаданные и массив загружаются отдельно.
- `POST /api/training/runs` доступен модератору; автоматический планировщик использует ту же серверную проверку пригодности набора. Публичный клиент не может менять активную модель.
