# Размещение DosYm PWA

## Текущая готовность

PWA, API и обработчик можно запустить локально. Production-секреты и облачные подключения в репозитории не хранятся; этот документ не означает, что сайт уже опубликован. До внешнего подключения автор должен создать ресурсы у поставщиков, установить секреты и проверить реальный OAuth/Drive доступ. Не публикуйте пользовательский пилот, пока не согласованы уведомление о данных, сроки хранения, запросы на удаление и политика резервного копирования. Техническое поведение согласия и удаления описано в `docs/DATA_RETENTION.md`.

## Схема сервиса

- **Vercel**: Next.js интерфейс и небольшие запросы через `pwa/app/api/[...path]/route.ts`.
- **Python backend**: постоянно доступные API, очередь извлечения/обучения, проверка видео и прямой resumable upload. Большие части видео и большие массивы обходят лимиты тела/времени Vercel Functions.
- **Google Drive**: исходные видеозаписи в ограниченной папке. Текущий `DriveStorage` использует серверный OAuth refresh token с доступом к папке. Это централизованная учётная запись хранения, а не личный Диск каждого загружающего.
- **PostgreSQL**: аккаунты, роли, права, статусы, задания, аудит и бинарные NumPy-артефакты. Браузерный ключ Supabase не получает прямые права на эти таблицы; backend соединяется собственным закрытым `DATABASE_URL`.
- **Вход**: оператор выбирает `DOSYM_AUTH_PROVIDER=supabase` или `google`. Первый режим сохраняет Supabase PKCE; второй проводит Google OAuth через FastAPI и выдаёт короткую подписанную сессию. Google-вход запрашивает только `openid email profile`. Выбор провайдера серверный — посетитель не переключает способ входа.
- **Тренер TensorFlow**: отдельный долгоживущий процесс, использующий тот же backend-код и базу; при нехватке классов/независимых исполнителей задача остаётся в ожидании.

Путь данных: Google login → серверная роль → прямой защищённый upload → модерация → MediaPipe/сохранение координат → при отдельном согласии набор кандидата. Видео удаляется отдельно после готовых и проверенных координат и подтверждённой резервной копии. Удаление источника не удаляет артефакт. Отзыв исключает материал из публикации и новых обучающих запусков, но не может задним числом убрать его вклад из уже обученных весов.

## Подготовка Vercel

1. Импортируйте GitHub-репозиторий в Vercel; задайте Root Directory `pwa` и включите доступ к файлам репозитория за пределами этого каталога. Скрипт сборки читает исходный аватар из `../web/` и лицензионную модель из `../web/models/`.
2. Используйте lockfile (`package-lock.json`) и команды `npm ci`, `npm run build`. Не включайте локальную SQLite базу, видео или `.env.local` в Git.
3. Добавьте HTTPS `NEXT_PUBLIC_UPLOAD_ORIGIN` (публичный адрес Python API) и `BACKEND_URL` для короткого прокси. Только для режима Supabase добавьте `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Не добавляйте Google refresh token, DB password или signing key с префиксом `NEXT_PUBLIC_`.
4. Для режима Google задайте на backend `DOSYM_AUTH_PROVIDER=google`, `DOSYM_GOOGLE_CLIENT_ID`, `DOSYM_GOOGLE_CLIENT_SECRET`, `DOSYM_GOOGLE_REDIRECT_URI=https://<api-domain>/auth/google/callback`, `DOSYM_FRONTEND_URL=https://<vercel-domain>` и разрешите этот frontend в `DOSYM_ALLOWED_ORIGINS`. В Google OAuth Console зарегистрируйте callback именно API, а не Vercel frontend. Для режима Supabase настройте Google OAuth callback в Supabase и Google Console.
5. Пока consent screen имеет статус Testing, разрешённые адреса вносятся в test users Google Auth Platform; только эти аккаунты смогут пройти вход. Перед публичным запуском проверьте требования Google к публикации и верификации. Production Google вход требует HTTPS API и frontend.
6. Python API должен разрешить точные production origins через `DOSYM_ALLOWED_ORIGINS`. Прямой upload, статусы и массивы обслуживаются этим доменом; включите HTTPS, ограничения сети и пригодную CORS-конфигурацию.

## Python API и обработчик

Для production задайте через секрет-хранилище backend:

- `DOSYM_ENV=production`, `DOSYM_LOCAL_AUTH=0`, `DOSYM_STORAGE=drive`;
- `DOSYM_PUBLIC_BACKEND=https://<api-domain>`;
- `DOSYM_ALLOWED_ORIGINS=https://<vercel-domain>`;
- закрытые `DATABASE_URL`, `DOSYM_SIGNING_KEY` (случайный, постоянный, минимум 32 символа);
- выберите ровно один режим входа через `DOSYM_AUTH_PROVIDER`. Supabase mode требует `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Google mode требует `DOSYM_GOOGLE_CLIENT_ID`, `DOSYM_GOOGLE_CLIENT_SECRET`, `DOSYM_GOOGLE_REDIRECT_URI`, `DOSYM_FRONTEND_URL` и `DOSYM_MODERATOR_EMAIL`;
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN`, `GOOGLE_DRIVE_FOLDER_ID` для выделенной учётной записи хранения с доступом к папке.

Запуск API: `python -m backend.run --host 0.0.0.0 --port 8765`. Запуск отдельного TensorFlow процесса: `python -m backend.training`. Установить `backend/requirements.txt` для API; для отдельной среды тренера Python 3.12 и `backend/requirements-training.txt`. Нужны постоянные диск/БД и настройка периодических резервных копий. Платформа должна поддерживать долгоживущие процессы и большие временные файлы; Vercel Functions для Python worker не подходят.

## База данных и хранение

Создайте PostgreSQL и примените `db/migrations/001_public_pwa.sql` ролью backend/владельца схемы. Не применяйте ключ браузера. RLS и revoke в миграции закрывают таблицы от ролей Supabase `anon`/`authenticated`, но сама миграция пока не проверялась на внешнем сервере PostgreSQL. Перед запуском сверить её с используемой версией PostgreSQL/Supabase и пройти тесты прав.

Drive OAuth client и папка должны принадлежать оператору и иметь квоту/политику хранения, достаточную для пилота. Серверные Drive credentials отделены от Google-входа и не должны передаваться участникам. Refresh token даёт доступ в рамках выданного scope; хранить его только в секрет-хранилище, ограничить доступ и иметь процедуру отзыва/ротации. Проверить resumable-сессию, квоту, удаление/восстановление и фактический доступ к папке на отдельной тестовой учётной записи. Не использовать пользовательские ролики до этого smoke-test.

Локальная автоматическая копия артефакта — файл рядом с локальной SQLite базой, не защита от потери диска. Production удаление видео блокируется, пока оператор не внедрит проверенную резервную копию артефактов и процедуру подтверждения. Запланируйте восстановление БД и файлов и протестируйте его на тестовом контуре до включения кнопки удаления.

## Роли и выпуск

Первый модератор назначается backend по подтверждённому email, заданному вне репозитория; после привязки авторизации следует сверить OAuth subject и результат первого входа на staging. В этом локальном проекте адрес хранится только в исключённом `data/pwa/private-settings.json`. Не передавайте содержимое файла и токены в тикеты/логи.

Переобучение создаёт отдельный кандидат с метриками, но текущая версия намеренно не переключает активную модель автоматически. До публичного обещания распознавания нужен независимый размеченный контрольный набор, пороги качества по классам, одобрение выпуска и проверенный откат модели. MediaPipe извлечение landmarks — это preprocessing, само по себе оно не означает обучение весов для каждого ролика.

## Размещение PWA без ML-сервера

Если `BACKEND_URL` отсутствует, но заданы `NEXT_PUBLIC_SUPABASE_URL` и
`NEXT_PUBLIC_SUPABASE_ANON_KEY`, PWA обслуживает `/api/auth/config` самостоятельно.
`/api/me` проверяет токен через Supabase Auth `/auth/v1/user` и возвращает только
роль участника. Метаданные аккаунта никогда не назначают модератора.
После подключения `BACKEND_URL` конфигурация и роли снова обслуживаются Python API.
Этот режим позволяет проверить Google-вход до размещения worker, но загрузки,
модерация, словарь из БД и обработка требуют доступного backend.

Для Google OAuth в Supabase включите Google, задайте Client ID/Secret и точный
callback из панели провайдера в Google Cloud. В Auth → URL Configuration задайте
Site URL и разрешённый `<site>/auth/callback`. После добавления публичных
переменных Vercel требуется новая сборка. Секрет OAuth хранится в Supabase Auth,
не в публичных переменных PWA. Режим Google Cloud Testing ограничивает вход
списком тестовых пользователей.

`https://dosym-seven.vercel.app`; публичные параметры Supabase и адрес возврата
настроены, Google-провайдер включён, реальная Google-сессия подтверждена.
Callback учитывает автоматический PKCE-обмен Supabase и не использует код дважды.

бэкапы и установка PWA на iOS/Android пока не проверены в облаке.
